# Lab 10: Mixed C and RISC-V Assembly Inspection

## Goal

Understand the RV64 calling convention used when C code and hand-written RISC-V assembly call functions.

This lab has two separate teaching purposes:

1. **Pass data between C and assembly.** C calls `asm_add_three(100, 20, 1)`. The three 64-bit `long` arguments enter the hand-written assembly function in `a0`, `a1`, and `a2`. The assembly function returns the 64-bit `long` value `121` to C in `a0`.
2. **Preserve registers across assembly function calls.** `check_preserves_s1` calls `broken_helper`. This path demonstrates why a callee that changes a callee-saved register such as `s1` must restore it before returning.

These are related but different parts of the calling convention. The first purpose explains how values cross the C/assembly boundary. The second purpose explains how functions avoid destroying register state that another function expects to survive a call.

Week 3 stays at the static build/disassembly layer. You will compile C and `.S` files into RV64 object files, inspect symbols and disassembly, and identify a callee-saved register violation without using QEMU yet.

By the end of this lab, students should understand:

- how C passes 64-bit integer arguments to a function implemented in `.S`
- how assembly returns a 64-bit integer value to C
- why an assembly function that calls another function must protect `ra`
- which registers are caller-saved
- which registers are callee-saved
- why assembly code must follow the same calling convention as compiler-generated C code

Week 4 will use QEMU and GDB remote debugging to observe live register values while a target is running.

## Two Teaching Examples / 两个教学示例

Build the lab:


### Example 1: C Arguments and Assembly Return Value / C 参数与汇编返回值

The C file declares and calls a function implemented in `asm_helpers.S`:

```c
long asm_add_three(long first, long second, long third);

g_add_result = asm_add_three(100, 20, 1);
```

At the function-call boundary, the RV64 calling convention gives these values specific locations:

```text
a0 = 100   first argument
a1 = 20    second argument
a2 = 1     third argument
```

The hand-written assembly adds the values and leaves the result in `a0`:

```asm
asm_add_three:
    add a0, a0, a1
    add a0, a0, a2
    ret
```

When the function returns, `a0 = 121`. The C code stores that return value in `g_add_result`.

This is the complete data path:

```text
C arguments 100, 20, 1
  -> RV64 registers a0, a1, a2
  -> hand-written assembly
  -> return value 121 in a0
  -> C variable g_add_result
```

### Example 2: Register-Preservation Failure / 寄存器保存错误

The C file also declares:

```c
int check_preserves_s1(void);
```

`check_preserves_s1` is implemented in `asm_helpers.S`. It sets `s1` to a sentinel value, calls `broken_helper`, then checks whether `s1` survived the call.

`broken_helper` is intentionally wrong:

```asm
broken_helper:
    li s1, 0x0badc0de
    li a0, 7
    ret
```

On RV64, `s1` is callee-saved. A function that changes it must restore it before returning.

The static bug to find:

```text
broken_helper writes s1
broken_helper does not save old s1
broken_helper does not restore old s1 before ret
```

## Concept Warmup

### ISA, API, and ABI / 指令集、源码接口与二进制接口

**ISA** is short for **Instruction Set Architecture**. It defines the machine that software can program:

```text
which registers exist
which instructions exist
what add, ld, sd, bne, and other machine instructions do
how instructions are encoded
```

For example, the RISC-V ISA defines an integer register named `x10` and defines how an `add` instruction operates. The `RV64IM` ISA selected in this lab means:

```text
RV64   integer registers and addresses are 64 bits wide
I      base integer instruction set
M      integer multiply and divide extension
```

**API** is short for **Application Programming Interface**. It describes a source-level interface. This C declaration is an API visible to a C programmer:

```c
long asm_add_three(long first, long second, long third);
```

**ABI** is short for **Application Binary Interface**. It defines how separately compiled code cooperates after source code has become machine instructions. An ABI includes rules such as:

```text
where function arguments are placed
where return values are placed
which registers the caller or callee must preserve
how the stack pointer is aligned
how large C types and pointers are
which ELF object-file format is used
```

For the API above, the RV64 LP64 ABI maps the source-level interface to machine-level locations:

```text
first argument   -> a0
second argument  -> a1
third argument   -> a2
return value     -> a0
```

The distinction can be remembered like this:

| Layer | Main question | Lab 10 example |
| --- | --- | --- |
| ISA | What instructions and registers does the CPU provide? | RV64IM provides 64-bit integer registers and instructions such as `add`, `sd`, and `ld`. |
| API | What function can source code call? | `long asm_add_three(long, long, long)` |
| ABI | How does compiled code make that call? | Put arguments in `a0/a1/a2`, return through `a0`, and follow register/stack rules. |

This is also why the Makefile has two different options:

```text
-march=rv64im   choose the ISA and instruction set
-mabi=lp64      choose the binary calling convention and C data model
```

一句话记忆：

```text
ISA：CPU 提供哪些寄存器和指令。
API：源代码可以调用什么函数。
ABI：编译后的代码怎样传参数、返回、保存寄存器和使用栈。
```

### Calling Convention / 调用约定

A calling convention is the function-call part of an ABI. It is an agreement between caller and callee about how a function call works at the machine-instruction level.

For RV64, the practical model is:

```text
a0-a7       argument registers and return-value registers
t0-t6       temporary registers, caller-saved
s0-s11      saved registers, callee-saved
ra          return address register
sp          stack pointer
pc          current instruction address
```

This lab focuses on register preservation. `broken_helper` violates the callee-saved rule for `s1`.

### RV64 Stack Alignment / RV64 栈对齐

The standard RV64 ABI requires `sp` to be **16-byte aligned**, meaning that its address is a multiple of 16:

```text
sp % 16 == 0
```

Equivalently, the lowest four bits of the address are zero. For example, `0x1000` and `0x0fe0` are 16-byte-aligned addresses.

The ABI requires a function to receive an aligned `sp` and keep it aligned. This allows every function it calls to rely on the same stack rule.

`check_preserves_s1` must save three RV64 registers:

```text
ra   8 bytes
s0   8 bytes
s1   8 bytes
------------
     24 bytes
```

However, subtracting 24 would break 16-byte alignment:

```text
entry sp:       0x1000   aligned
0x1000 - 24 =  0x0fe8   not aligned to 16 bytes
```

The function therefore rounds the stack-frame size up from 24 to 32 bytes:

```asm
addi sp, sp, -32
```

```text
entry sp:       0x1000   aligned
0x1000 - 32 =  0x0fe0   still aligned
```

The resulting stack frame is:

```text
higher addresses

sp + 32   sp value on function entry
          ---------------------------
sp + 24   saved ra   8 bytes
sp + 16   saved s0   8 bytes
sp + 8    saved s1   8 bytes
sp + 0    padding    8 bytes
          ---------------------------
sp        current stack pointer, still aligned to 16 bytes

lower addresses
```

The padding is not another register. It is unused space that makes the total frame size a multiple of 16. Before returning, the function releases the same 32 bytes:

```asm
addi sp, sp, 32
```

一句话记忆：栈地址必须按 16 bytes 对齐；保存三个 8-byte 寄存器需要 24 bytes，所以栈帧向上补齐到 32 bytes。

### Who Maintains the Calling Convention? / 谁维护调用约定

Caller-saved and callee-saved rules apply to every machine-level function call. They do not apply only to functions written in assembly. A function originally written in C must follow the same RV64 ABI after the compiler turns it into machine instructions.

The difference is who performs the work:

```text
C function          the compiler generates the required save/restore instructions
assembly function   the assembly programmer writes the required instructions
```

For each call, caller and callee are roles, not programming languages. The same function can be a callee when another function calls it and then become a caller when it calls a helper.

| Call boundary | Who maintains the caller side? | Who maintains the callee side? |
| --- | --- | --- |
| C calls C | C compiler | C compiler |
| C calls assembly | C compiler | Assembly programmer |
| Assembly calls C | Assembly programmer | C compiler |
| Assembly calls assembly | Assembly programmer | Assembly programmer |

For an ordinary C-only program, the programmer normally does not write register-saving instructions by hand. The compiler still follows these rules. For example:

```c
int f(void) {
    int x = 10;
    int y = helper();
    return x + y;
}
```

The value of `x` is still needed after `helper()` returns. The compiler may keep `x` on the stack, recompute it, or place it in a callee-saved register. If it chooses `s1`, one possible assembly shape is:

```asm
f:
    addi sp, sp, -16
    sd   ra, 8(sp)        # Save all 64 bits of the return address.
    sd   s1, 0(sp)        # Save all 64 bits of the caller's original s1.

    li   s1, 10           # Keep C variable x in s1.
    call helper           # helper must return with s1 unchanged.
    add  a0, a0, s1      # a0 contains y; calculate y + x.

    ld   s1, 0(sp)        # Restore the value that f's caller had in s1.
    ld   ra, 8(sp)
    addi sp, sp, 16
    ret
```

The exact instructions chosen by a compiler may differ, but the ABI responsibility does not change. If a value in a caller-saved register must survive a call, the caller protects it. If a callee changes a callee-saved register, the callee restores it.

In this lab, the roles are:

| Function | Role in this lab | Responsibility |
| --- | --- | --- |
| `main` | C caller | The compiler places arguments in `a0/a1/a2` and generates the calls. |
| `asm_add_three` | Assembly callee | It reads `a0/a1/a2`, returns through `a0`, and does not need to save `ra` because it calls no other function. |
| `check_preserves_s1` | Callee of `main`, then caller of `broken_helper` | It preserves the `s1` value belonging to `main`, saves `ra` before its nested call, and expects `broken_helper` to preserve `s1`. |
| `broken_helper` | Assembly callee | It should preserve `s1`, but intentionally violates that rule. |

This is why a broken assembly function can corrupt a C program. The C compiler may keep a C variable in `s1` because the ABI promises that a callee will preserve it. If hand-written assembly changes `s1` without restoring it, that C variable can silently change even though the C source code never assigned a new value to it.

### Register Responsibility / 寄存器责任

The question is not "which registers can I use freely?" The better question is:

```text
Who is responsible for protecting this register across a function call?
```

Practical RV64 register table:

```text
a0-a7   arguments and return values, caller-saved
t0-t6   temporary registers, caller-saved
s0-s11  saved registers, callee-saved
ra      return address, caller-saved in the ABI sense
sp      stack pointer, must stay balanced
pc      current instruction address
```

Meaning:

```text
a-registers can pass arguments and return values, but calls may change them.
t-registers are temporary; callers should not expect them to survive calls.
s-registers may be used by a callee, but the callee must restore them.
sp must point to a valid stack and be restored before returning.
ra tells ret where to go back.
```

### Caller-Saved Register / 调用者保存寄存器

Caller means the function that makes a function call.

Caller-saved means:

```text
If the caller still needs the value after a call,
the caller must save it before the call.
```

Important RV64 caller-saved registers:

```text
a0-a7
t0-t6
ra
```

After a call, the caller should not assume `a0` still contains the old argument value. `a0` may contain the callee's return value.

### Callee-Saved Register / 被调用者保存寄存器

Callee means the function being called.

Callee-saved means:

```text
If the callee changes the register,
the callee must restore the original value before returning.
```

Important RV64 callee-saved registers:

```text
s0-s11
```

A correct callee that wants to use `s1` usually does something like this:

```asm
addi sp, sp, -16
sd   s1, 8(sp)

li   s1, 0x0badc0de
# use s1

ld   s1, 8(sp)
addi sp, sp, 16
ret
```

Lab 10 is built around this exact rule. `broken_helper` changes `s1` but does not restore it.

### Assembly Reading Notes / 汇编阅读注释

RISC-V load/store instructions use `offset(base)` address syntax. On RV64, saving a complete 64-bit integer register requires `sd` and `ld`:

```asm
sd source_register, offset(base_register)
ld destination_register, offset(base_register)
```

For example:

```asm
sd ra, 24(sp)
ld ra, 24(sp)
```

`24(sp)` is one memory-address operand. It means `memory[sp + 24]`; it is not two separate operands. `sd` stores one 64-bit doubleword, which is 8 bytes. `ld` loads one 64-bit doubleword.

```text
sd ra, 24(sp)   把 ra 的 64-bit 值保存到地址 sp + 24
ld ra, 24(sp)   从地址 sp + 24 读回 64-bit 值到 ra
```

Use this table as a quick reference while reading `asm_helpers.S`:

| Instruction | Meaning |
| --- | --- |
| `add a0, a0, a1` | Add the values in `a0` and `a1`, then write the result to `a0`. |
| `addi sp, sp, -32` | Add the immediate value `-32` to `sp`; move the stack pointer down and allocate a 32-byte stack frame. |
| `sd ra, 24(sp)` | Store all 64 bits of `ra` into memory at `sp + 24`; save the return address in the stack frame. |
| `ld ra, 24(sp)` | Load 64 bits from memory at `sp + 24` into `ra`; restore the return address. |
| `li s1, value` | Load an immediate constant into `s1`. |
| `call broken_helper` | Call `broken_helper`; `ra` is updated with the return address. |
| `bne s1, t0, label` | Branch to `label` if `s1` is not equal to `t0`. |
| `li a0, 0` | Put `0` in `a0`; `a0` carries the integer return value. |
| `ret` | Return to the address in `ra`. |

The instruction names are short forms of their jobs:

```text
add   add registers
addi  add immediate
sd    store doubleword (64 bits)
ld    load doubleword (64 bits)
li    load immediate
bne   branch if not equal
j     unconditional jump
```

First read the correct C/assembly interface function:

```asm
asm_add_three:
    add a0, a0, a1          # a0 = first + second
    add a0, a0, a2          # a0 = first + second + third
    ret                     # Return to C with the result in a0.
```

At entry, `a0`, `a1`, and `a2` contain the three arguments supplied by C. Reusing `a0` for the calculation is valid because `a0` is caller-saved and is also the integer return-value register.

In this example the C arguments and return type are `long`, so LP64 gives each value a 64-bit representation. The `add` instructions operate on the full 64-bit registers.

`asm_add_three` does not create a stack frame or save `ra` because it is a leaf function: it does not call another function. Its own caller placed the return address in `ra`, and this function does not overwrite `ra` before `ret` uses it.

Read `check_preserves_s1` from top to bottom:

```asm
check_preserves_s1:
    addi sp, sp, -32         # Allocate a 32-byte, 16-byte-aligned stack frame.
    sd   ra, 24(sp)          # Save the 64-bit ra because call will change it.
    sd   s0, 16(sp)          # Save the caller's 64-bit frame pointer.
    sd   s1, 8(sp)           # Save all 64 bits of callee-saved s1.
    addi s0, sp, 32          # Set s0/fp to the stack pointer value on entry.

    li   s1, 0x39139139      # Put a known sentinel value in s1.
    call broken_helper       # Call another function; call updates ra.

    li   t0, 0x39139139      # Put the expected value in temporary register t0.
    bne  s1, t0, bad_preserve # Branch if broken_helper changed s1.

    li   a0, 0               # Return 0 when s1 was preserved.
    j    done_preserve       # Skip the failure case.

bad_preserve:
    li   a0, 1               # Return 1 when s1 was not preserved.

done_preserve:
    ld   s1, 8(sp)           # Restore all 64 bits of the caller's original s1.
    ld   s0, 16(sp)          # Restore all 64 bits of the caller's original s0/fp.
    ld   ra, 24(sp)          # Restore the saved 64-bit return address.
    addi sp, sp, 32          # Release the 32-byte stack frame.
    ret                      # Return through ra.
```

The important sequence is:

```text
put a known value in s1
call broken_helper
compare s1 with the known value
return 1 if the value changed
```

Now read the intentionally incorrect callee:

```asm
broken_helper:
    li s1, 0x0badc0de        # BUG: overwrite a callee-saved register.
    li a0, 7                 # Put this function's return value in a0.
    ret                      # Return without restoring the old s1.
```

`s1` is callee-saved, so `broken_helper` may use it only if it saves the old value and restores that value before `ret`. The bug is not that the function uses `s1`; the bug is that it changes `s1` and returns without restoring it.

The RV64 stack frame above is:

```text
sp + 24   saved ra   (8 bytes)
sp + 16   saved s0   (8 bytes)
sp + 8    saved s1   (8 bytes)
sp + 0    padding    (8 bytes)
```

The padding keeps the 32-byte frame aligned to the RV64 ABI's 16-byte stack alignment. `sd` and `ld` are required here because `ra`, `s0`, and `s1` are 64-bit registers. Using `sw`/`lw` would preserve only 32 bits and could corrupt a 64-bit address or saved value.

Step 7: Explain the bug.

Expected explanation:

```text
s1 is callee-saved in RV64.
broken_helper is a callee.
broken_helper modifies s1.
broken_helper does not restore the original s1 before ret.
Therefore broken_helper violates the calling convention.
```

## Fix Idea

The broken helper should save and restore `s1`:

```asm
broken_helper:
    addi sp, sp, -16
    sd   s1, 8(sp)
    li   s1, 0x0badc0de
    li   a0, 7
    ld   s1, 8(sp)
    addi sp, sp, 16
    ret
```

This lab intentionally leaves the bug in place so students can practice finding it.

## Review Questions

1. Which RV64 registers carry the first three integer arguments?

   Answer: `a0`, `a1`, and `a2`.

2. What value does `asm_add_three(100, 20, 1)` return, and where is that value placed?

   Answer: it returns `121` in `a0`.

3. Which RV64 register carries the integer return value?

   Answer: `a0`.

4. Which RV64 register carries the return address?

   Answer: `ra`.

5. Is `s1` caller-saved or callee-saved?

   Answer: callee-saved.

6. Why is clobbering `s1` a bug here?

   Answer: `s1` is callee-saved, so a function that changes it must restore it before returning.

7. How should `broken_helper` fix the bug?

   Answer: save `s1` before modifying it and restore `s1` before `ret`.
